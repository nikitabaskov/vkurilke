# ВКурилке 🚬

Telegram-бот и Mini App для своей компании. Большая кнопка отмечает присутствие, рядом видны участники комнаты и время их перекура. Go-сервис, SQLite и встроенная статика — один процесс, без Redis, отдельного Node-сервера и CGO.

Согласованные правила: [docs/DECISIONS.md](docs/DECISIONS.md).

Превью с тестовыми участниками: [темная тема](docs/preview-dark.png) · [светлая тема](docs/preview-light.png).

## Что работает

- Вход по приглашению, несколько комнат и один активный статус на человека.
- Владелец и администраторы комнаты, назначение прав, исключение и повторное добавление участников. Исключение закрывает доступ по старой ссылке; администратор может вернуть человека по ID.
- Кнопка «Я в курилке» / «Я вернулся», счетчик времени, «Спускаюсь (+1)» на 5 минут в боте.
- Проверка присутствия через 15 минут, 3 минуты на ответ после доставки вопроса. «Да» назначает новую проверку, молчание выключает статус.
- Одна карточка текущего сеанса в личной переписке. Она обновляется при изменениях, закрывается после ухода последнего участника; старые кнопки не действуют.
- Отдельные настройки уведомлений о начале сеанса, приходах и уходах. Проверки присутствия остаются включенными.
- Светлая и темная темы Telegram, аватары с запасным отображением первой буквы, тактильный отклик. Активные участники сверху, обновление раз в 5 секунд.
- Таймеры, очередь доставки, авторизация и Telegram update offset сохраняются в SQLite и переживают перезапуск.

## Запуск на VPS

Нужны Docker с Compose, домен, направленный на VPS, и токен бота от [BotFather](https://t.me/BotFather). Для автоматического HTTPS освободите порты 80 и 443.

1. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `BASE_URL`, `DOMAIN`. `BASE_URL` — адрес вида `https://smoke.example.com`, `DOMAIN` — тот же домен без протокола.
2. В `ADMIN_IDS` укажите свой **числовой Telegram User ID**, не username и не ID бота. Можно указать несколько через запятую. Если ID пока неизвестен, оставьте поле пустым: запустите сервис, отправьте боту `/id`, затем заполните поле и повторите команду запуска.
3. Запустите:

   ```bash
   docker compose --profile https up -d --build
   docker compose logs -f app
   ```

4. Отправьте боту `/start`, откройте Mini App кнопкой «Открыть курилку» или кнопкой меню. Администратору приложения доступно создание первой комнаты.
5. Создайте «Общага», откройте настройки комнаты и скопируйте приглашение. Участники переходят по ссылке, запускают бота и открывают приложение.

Бот сам устанавливает кнопку меню и команды. Для дополнительной кнопки запуска в профиле можно настроить Main Mini App в BotFather, указав `BASE_URL` ([документация Telegram](https://core.telegram.org/bots/webapps#launching-the-main-mini-app)).

Если HTTPS уже обслуживает Nginx/Caddy на хосте, запускайте `docker compose up -d --build` без профиля `https` и направьте reverse proxy на `127.0.0.1:8080` (или `PORT`). Mini App и API должны быть на одном origin.

Используйте отдельного бота для приложения. На старте сервис отключает webhook, сохраняя накопленные updates, и работает через long polling. Запускайте **одну реплику** приложения с локальным SQLite volume.

### Команды бота

| Команда | Действие |
| --- | --- |
| `/start` | Регистрация и кнопка Mini App |
| `/start <код>` или просто код | Вступление по приглашению |
| `/id` | Ваш числовой Telegram User ID |
| `/toggle_notify` | Выключить социальные уведомления / включить начало сеанса и приход |

## Локальная сборка и проверки

Требуются Go 1.25+ и Node.js 22.12+ (Docker собирает на Go 1.27 и Node.js 24). Node нужен только при сборке.

```bash
make build
make test
make check
```

`make check` запускает проверку TypeScript, production build, `go vet` и Go race tests. Для `-race` нужен системный C-компилятор; обычная сборка и SQLite работают без CGO.

Перед локальным запуском экспортируйте значения из `.env` в окружение. Приложение читает переменные окружения, а не сам файл `.env`. Если файл содержит только доверенные shell-совместимые значения:

```bash
set -a
. ./.env
set +a
./bin/vkurilke
```

Для редактирования фронтенда: `npm --prefix web run dev`. Vite проксирует `/api` на порт 8080. Авторизация требует настоящего Telegram `initData`; обхода авторизации и демонстрационных пользователей в production нет. Без Telegram показывается экран перехода к боту. Для проверки внутри Telegram нужен HTTPS-адрес разработки и отдельный тестовый бот.

## Хранение и эксплуатация

SQLite находится в Docker volume `app_data`; обычный перезапуск или пересборка его сохраняют. `docker compose down -v` удаляет данные. Для простой согласованной резервной копии остановите `app`, сохраните содержимое volume и снова запустите сервис; не копируйте только основной `.db` из работающего WAL-хранилища.

`GET /healthz` проверяет HTTP и соединение с БД. Ошибки Telegram и повторные попытки видны в `docker compose logs app`. Настройки интервалов применяются после перезапуска; уже назначенные дедлайны сохраняются до следующего перехода/подтверждения.

Доставка повторяется при временных ошибках и ограничениях Telegram. При блокировке бота пользователем его присутствие выключается: проверить его больше невозможно. Повторный `/start` восстанавливает канал. В редком случае аварии между отправкой сообщения и сохранением его ID возможен дубль: у Telegram `sendMessage` нет механизма идемпотентного повтора. Изменения статусов и callback-переходы защищены от повторов.

Истории посещений нет: завершенный сеанс хранится только до обработки его уведомлений. Старые сообщения остаются в Telegram без действующих кнопок присоединения.

## API

Авторизация: `POST /api/auth` с `{ "init_data": "..." }` возвращает `{ "token": "..." }`. Остальные приватные запросы передают `Authorization: Bearer <token>`.

`initData` проверяется по HMAC-SHA256 и возрасту (не старше часа, допустимое опережение часов — 30 секунд), согласно [Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app). Случайная сессия живет 24 часа; в БД сохраняется только ее SHA-256. Пользовательские ID в запросах смены статуса не принимаются.

| Метод и путь | Назначение / тело |
| --- | --- |
| `GET /api/meta` | Публичное имя бота и интервалы |
| `GET /api/me` | Пользователь, настройки, право создавать комнаты |
| `GET /api/groups` | Доступные комнаты и роли; инвайт виден только управляющим |
| `POST /api/groups` | Создать комнату: `{ "name": "Общага" }` |
| `POST /api/groups/join` | Вступить: `{ "code": "..." }` |
| `POST /api/groups/{id}/invite` | Заменить приглашение |
| `POST /api/groups/{id}/members` | `{ "user_id": 123, "action": "add\|remove\|admin\|member" }` |
| `DELETE /api/groups/{id}/membership` | Выйти из комнаты; владелец выйти не может |
| `GET /api/status?group_id=...` | Список участников, собственный активный статус, серверное время |
| `POST /api/status/change` | `{ "group_id": "...", "status": "going\|smoking\|idle", "duration_minutes": 5 }` |
| `POST /api/status/confirm` | `{ "token": "...", "here": true }` |
| `PUT /api/settings/notifications` | Все три поля: `{ "session": true, "arrival": true, "departure": false }` |
| `POST /api/settings/toggle-notifications` | Переключить социальные уведомления |

`going` поддерживает длительности 3/5/10 минут; кнопка бота всегда выбирает 5. Все времена API — Unix seconds UTC. Mini App корректирует часы по `server_time`. Данные других комнат доступны только их участникам; чтение списка не меняет активную комнату пользователя.

## Структура

```text
cmd/app/          запуск, остановка, HTTP-сервер
internal/config/  переменные окружения
internal/api/     Telegram auth, REST, проверка запросов
internal/store/   SQLite, права, статусы, сеансы, очередь
internal/bot/     Telegram API, команды, кнопки, карточки
internal/worker/  таймеры и доставка с повторными попытками
web/              TypeScript, Tailwind/CSS, Vite, go:embed
docs/             согласованные правила
```
