# Развертывание ВКурилке на Bothost

Один контейнер обслуживает Telegram-бота, Mini App и API. Фронтенд собирается внутри Dockerfile и встраивается в Go-бинарник. Отдельно запускать Node.js, Compose или Caddy на Bothost не требуется.

Инструкция сверена с публичной документацией и формой «Создать нового бота» Bothost 13 сентября 2026 года. Ниже использованы названия полей этой формы.

## 1. Подготовить бота и репозиторий

1. Получите токен у [@BotFather](https://t.me/BotFather): создайте бота командой `/newbot` или используйте токен существующего бота ВКурилке.
2. Загрузите актуальный код проекта с корневым `Dockerfile` в свой GitHub/GitLab-репозиторий. Ветка, выбранная в Bothost, должна содержать эти изменения. Локальных изменений без отправки в Git хостинг не увидит.
3. Не загружайте `.env` и базу данных в Git. Секреты задаются в панели, перенос существующих данных описан ниже.
4. Зарегистрируйтесь на [Bothost](https://bothost.ru/).

Выберите тариф, в котором доступны **HTTPS-домен, переменные окружения и постоянное хранилище**. Для этого проекта ориентируйтесь на Basic или выше. Публичные страницы Bothost расходятся в описании бесплатного тарифа: [FAQ](https://bothost.ru/docs/faq) относит веб-домены к платным возможностям, а [главная страница](https://bothost.ru/) отдельно ограничивает постоянное хранилище платными тарифами. Перед оплатой проверьте эти возможности в кабинете; одного long polling без веб-домена недостаточно для Mini App.

## 2. Создать проект в Bothost

Заполняйте форму сверху вниз. Блок «Telegram аккаунт привязан» уже подтверждает привязку аккаунта; числовой **Telegram ID из этого блока** можно скопировать в `ADMIN_IDS`, чтобы стать администратором приложения.

| Поле | Значение |
| --- | --- |
| Название бота | `ВКурилке` — название в панели хостинга |
| Платформа | Telegram |
| Язык разработки | **Go** |
| Bot Token | Настоящий токен вашего бота от BotFather, а не пример из подсказки |
| Локация развертывания | Можно оставить выбранные Нидерланды (Амстердам); настройки приложения одинаковы для обеих локаций |
| Переменные окружения | Добавьте пары из шага 4 кнопкой «Добавить переменную окружения» |
| Git URL репозитория | `https://github.com/nikitabaskov/vkurilke.git` или URL своего форка |
| Ветка | **`master`** для текущей локальной ветки этого проекта; отправьте ее в Git перед деплоем. Для форка укажите ветку, куда отправили код |
| Описание | Необязательно; например, `Telegram-бот и Mini App для компании: кто сейчас в курилке` |

Не оставляйте `main` только потому, что это значение по умолчанию в форме: выбранная ветка должна существовать в удаленном репозитории и содержать подготовленные изменения.

В блоке «Дополнительные настройки» заполните:

| Поле | Значение |
| --- | --- |
| Использовать домен | **Включить** |
| Порт веб-приложения | **`8080`**, заменив предложенные формой `3000` |
| Кастомный домен | Свободный поддомен, например `vkurilke-yourname.bothost.tech`, **без `https://`**; замените `yourname` на свое имя. Либо оставьте пустым для автоматического домена — порядок ниже |
| Главный файл (точка входа) | Оставить пустым |
| Использовать собственный Dockerfile | **Включить** — на форме эта галочка изначально снята |

Сборка должна идти из корня репозитория, где лежат `Dockerfile`, `go.mod` и каталог `web`.

Поле «Главный файл» оставьте пустым: при собственном Dockerfile запуск задается его `ENTRYPOINT` — `/usr/local/bin/vkurilke`. Если форма требует исходный файл, укажите `cmd/app/main.go`, сохранив режим собственного Dockerfile. Не задавайте `go run` или `npm start` как команду запуска.

Bothost монтирует исходники в `/app`. Наш бинарник уже находится вне этой папки, а статика встроена в него, поэтому такой mount не скрывает результат сборки. См. [Dockerfile на Bothost](https://bothost.ru/docs/custom-dockerfile) и [правила точки входа](https://bothost.ru/docs/main-file-entrypoint).

## 3. Включить домен Mini App

В форме можно заранее указать поддомен платформы в поле «Кастомный домен». Это позволяет сразу заполнить `BASE_URL`:

```text
Кастомный домен: vkurilke-yourname.bothost.tech
BASE_URL:        https://vkurilke-yourname.bothost.tech
```

Выберите свое свободное имя вместо `yourname`. Если Bothost отклоняет занятое или недопустимое имя, измените **оба** значения. После создания проверьте фактически назначенный адрес в панели и его совпадение с `BASE_URL`.

Альтернатива — оставить «Кастомный домен» пустым. Bothost создаст автоматический адрес. Тогда создайте проект, скопируйте выданный HTTPS-адрес в `BASE_URL` и повторно разверните приложение. До заполнения `BASE_URL` первый запуск завершится ошибкой конфигурации; это ожидаемо. Не подставляйте вымышленный автоматический адрес по имени бота.

Bothost завершает HTTPS и передает запросы в HTTP-сервер контейнера. Сервер проекта уже слушает все интерфейсы и берет порт из `PORT`. Если панель предлагает HTTP-обертку, отключите ее: веб-сервер уже есть. См. [домены и порты](https://bothost.ru/docs/domains-and-ports) и [веб-приложения](https://bothost.ru/docs/web-apps-domains).

**Не вызывайте Telegram `setWebhook`.** Этот бот получает сообщения через long polling и при старте сам удаляет старый webhook, сохраняя ожидающие обновления. Домен здесь нужен для Mini App и API.

## 4. Задать переменные окружения

В разделе «Переменные окружения» каждую пару задавайте отдельной строкой: слева ключ, справа значение **без кавычек**. Следующую строку добавляйте зеленой кнопкой «Добавить переменную окружения».

| Переменная | Значение |
| --- | --- |
| `BASE_URL` | `https://vkurilke-yourname.bothost.tech` для выбранного свободного поддомена либо фактически выданный автоматический HTTPS-адрес; без пути и завершающего `/` |
| `PORT` | `8080`, как в настройках домена; Bothost передает выбранный порт автоматически |
| `DB_PATH` | **`/app/data/vkurilke.db`** |
| `ADMIN_IDS` | Скопируйте числовой **Telegram ID** из блока «Telegram аккаунт привязан» вверху формы; несколько ID через запятую |
| `CHECK_INTERVAL_MINUTES` | `15` — необязательно, это значение по умолчанию |
| `ANSWER_TIMEOUT_MINUTES` | `3` — необязательно, это значение по умолчанию |

Токен вводите в отдельное поле **Bot Token**: Bothost передает его как `BOT_TOKEN`, дополнительная строка с таким же ключом не нужна. `PORT` можно не дублировать, если панель передает `8080` из поля «Порт веб-приложения»; при явном задании оба значения должны совпадать.

`BASE_URL` задавайте явно: приложение не выводит его из автоматически установленного `DOMAIN`. Порт `:8080` в публичный HTTPS-адрес добавлять не нужно. См. [переменные окружения Bothost](https://bothost.ru/docs/environment-variables).

Кнопку «Загрузить из файла .env» использовать необязательно. Не импортируйте локальный `.env` без проверки: в нем могут быть VPS-домен и неподходящий путь базы. Импорт в панели заполняет переменные хостинга; само приложение файл `.env` не читает.

Если не знаете свой ID, временно оставьте `ADMIN_IDS` пустым. После запуска отправьте боту `/id`, добавьте полученное число в панель и повторно разверните приложение. Пока список пуст, никто не может создавать комнаты.

## 5. Проверить постоянное хранилище и запустить

**Обязательно переопределите `DB_PATH`.** По умолчанию Docker-образ использует `/data/vkurilke.db` для VPS. На Bothost база должна лежать в `/app/data/vkurilke.db`: платформа выделяет папку `data` и сохраняет ее при обновлениях из Git. База и таблицы создаются приложением автоматически. См. [хранение базы на Bothost](https://bothost.ru/docs/database-storage).

Приложение работает под пользователем `app` с UID **10001**, но контейнер стартует от root: `docker-entrypoint.sh` создает каталог из `DB_PATH`, назначает его владельцем `app` и только потом запускает бинарник без привилегий. Поэтому каталог, смонтированный хостингом от root, готовится автоматически — отдельных команд и обращения в поддержку обычно не требуется.

Ручное вмешательство нужно только если платформа сама запускает контейнер под непривилегированным пользователем и каталог данных ему недоступен. Тогда в административном терминале с root-доступом:

```sh
mkdir -p /app/data
chown -R 10001 /app/data
chmod 700 /app/data
```

Команды относятся только к каталогу данных этого бота. Обычный терминал пользователя `app` не сможет сменить владельца чужих файлов.

### Ошибка `unable to open database file: out of memory (14)`

Это не нехватка памяти: код `14` — `SQLITE_CANTOPEN`, то есть SQLite не смог создать или открыть файл базы; на нехватку памяти указывает код `7`. Увеличивать тариф по фразе «out of memory» не нужно. См. [коды ошибок SQLite](https://www.sqlite.org/rescode.html#cantopen).

Что проверить:

1. Разверните текущую версию из Git: образ с `docker-entrypoint.sh` чинит права каталога данных сам, а приложение при старте проверяет запись и пишет понятное сообщение вида `database directory /app/data is not writable`.
2. Во вкладке «Переменные» проверьте `DB_PATH=/app/data/vkurilke.db` без кавычек и пробелов.
3. Если после нового деплоя в логах осталась ошибка про недоступный каталог, а вкладка «Консоль» недоступна из-за `restarting`, напишите в поддержку, приложив ID проекта и текст без токена:

   > Go-бот запускается из собственного Dockerfile, `DB_PATH=/app/data/vkurilke.db`. При старте SQLite не может открыть файл базы, контейнер в `restarting`, консоль недоступна. Проверьте фактический mount `/app/data`: он должен быть доступен контейнеру на запись, включая файлы WAL/SHM. Просьба сохранить существующую базу, не удалять и не пересоздавать хранилище.

Не переносите базу в `/tmp` или другой непостоянный каталог ради обхода ошибки: данные пропадут при первом же перезапуске.

1. Остановите другие экземпляры с тем же токеном, в том числе локальный процесс или старый VPS.
2. Запускайте **одну реплику**: проект использует long polling и локальный SQLite.
3. Сохраните настройки и запустите развертывание.
4. В логах сборки проверьте завершение этапов Node.js и Go. В логах работы дождитесь `ВКурилке started` с портом и именем бота.
5. Откройте `https://ВАШ-ДОМЕН/healthz`. Ожидаемый ответ — `{"ok":true}`. Если в панели есть поле HTTP healthcheck, укажите `/healthz`.

Встроенный Docker healthcheck учитывает `PORT`. После смены порта измените также поле порта в панели и выполните новый деплой.

## 6. Проверить работу в Telegram

1. Отправьте боту `/start` и нажмите кнопку меню «ВКурилке 🚬» у поля ввода.
2. При необходимости получите `/id` и завершите настройку `ADMIN_IDS`.
3. Создайте комнату, отметьтесь в курилке и проверьте карточку в чате.
4. Скопируйте приглашение в настройках комнаты и проверьте вступление второго участника.
5. Перезапустите контейнер и убедитесь, что комната и участники сохранились. Перед приглашением всей компании проверьте также сохранность после «Обновить из Git».

Бот сам настраивает команды и кнопку меню с `BASE_URL`. Дополнительная настройка в BotFather для обычного запуска не нужна. Mini App открывайте внутри Telegram: в обычном браузере нет Telegram-авторизации. `/healthz` проверяет доступность HTTP-сервера, но не заменяет проверку ответов бота и Mini App.

## Обновления и резервные копии

Отправьте изменения в выбранную Git-ветку и нажмите «Обновить из Git» в Bothost. После изменения переменных, домена или порта выполните повторное развертывание. Если сменился домен, обновите `BASE_URL` и заново откройте Mini App из новой кнопки бота.

Перед обновлением с важными данными остановите бот и скачайте **весь каталог `data`** через файловый менеджер. SQLite использует WAL: не копируйте только `vkurilke.db` у работающего приложения. Если присутствуют `vkurilke.db-wal` и `vkurilke.db-shm`, сохраняйте их вместе с базой после остановки. Храните резервную копию отдельно от Bothost.

Для переноса с VPS или восстановления:

1. Остановите исходный бот и получите согласованную копию данных; для VPS есть [инструкция резервного копирования](DEPLOY.md#данные-и-резервные-копии).
2. Остановите бот на Bothost и сохраните его текущий каталог `data`, если он не пуст.
3. Восстановите согласованный комплект SQLite-файлов в `/app/data` через файловый менеджер. Не смешивайте WAL/SHM от другой базы с восстанавливаемой копией.
4. Проверьте `DB_PATH=/app/data/vkurilke.db` и права UID 10001, затем запустите только экземпляр на Bothost.
5. Проверьте `/healthz`, ответы бота и прежние комнаты в Mini App.

Не удаляйте проект/хранилище для обычного обновления. Сохранение папки между деплоями не заменяет резервную копию.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| `BASE_URL must be an HTTPS origin` | Укажите фактический адрес с `https://`, без `/api`, query-параметров и порта контейнера |
| `BOT_TOKEN is required` / Telegram `401` | Передан ли правильный токен через настройки Bothost |
| `permission denied` / `unable to open database file` / `readonly database` | Путь `/app/data/vkurilke.db`, существование постоянного каталога и доступ контейнера на запись; разбор — в разделе [про `out of memory (14)`](#ошибка-unable-to-open-database-file-out-of-memory-14) |
| Комнаты пропали после обновления | Проверьте `DB_PATH` и постоянное хранилище; остановите бот перед восстановлением копии |
| `502` / `504` | Контейнер работает, в логах завершена настройка Telegram, порт панели совпадает с `PORT`, домен включен |
| Telegram `409 Conflict` | Остановите другие экземпляры с тем же токеном; не устанавливайте webhook |
| Бот отвечает, Mini App не открывается | HTTPS-домен доступен, `BASE_URL` совпадает с ним, Mini App открыт через новую кнопку внутри Telegram |
| Нельзя создать комнату | В `ADMIN_IDS` указан числовой ID пользователя, настройки применены новым развертыванием |
| Ошибка запуска `main.py`, `index.js` или `/app/...` | Включите собственный Dockerfile; фактическая команда запуска — `/usr/local/bin/vkurilke` |

Если сборка или запуск падает, сначала откройте соответствующие логи в Bothost. Для обращения в поддержку достаточно текста ошибки и ID проекта; токен бота не публикуйте.
