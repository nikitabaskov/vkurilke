# Согласованная логика «ВКурилке»

- Telegram-бот пишет только в личные сообщения. Mini App — основной интерфейс.
- Вход в комнаты по приглашению. Нет автоматического добавления в общую комнату.
- Комнаты создает администратор приложения, заданный через `ADMIN_IDS`.
- Владелец назначает администраторов. Владелец и администраторы приглашают, добавляют и исключают участников. Администратор комнаты не может исключить владельца или другого администратора.
- Пользователь состоит в нескольких комнатах; активен только в одной. Просмотр другой комнаты не меняет статус. Включение статуса в другой комнате атомарно завершает прежнее участие.
- Большая кнопка сразу включает «В курилке», повторное нажатие выключает.
- «Спускаюсь (+1)» в боте включает `going` на 5 минут. По истечении таймера или нажатию «Я на месте» статус становится `smoking`.
- Для `smoking` показывается время с момента прихода, для `going` — обратный отсчет.
- Через 15 минут бот спрашивает «Все еще в курилке?». После доставки вопроса ждет 3 минуты. «Да» назначает следующую проверку через 15 минут, отсутствие ответа завершает участие. Интервалы настраиваются.
- Общий сеанс начинается с первого `smoking` и продолжается, пока кто-то курит или спускается. Уход первого участника не завершает сеанс.
- Каждый сеанс — одна карточка в личной переписке. Приходы и уходы не присылаются отдельными сообщениями: карточка редактируется. В активной карточке — кто курит, кто спускается и сколько просидели ушедшие; в завершенной — длительность сеанса и сколько просидел каждый (считается только время в `smoking`, повторные приходы суммируются). Участники сеанса, включая основателя, получают карточку сразу; настройка сеанса отвечает только за сеансы, к которым человек не присоединился.
- Mini App открывается кнопкой меню у поля ввода; в сообщениях бота кнопки открытия нет. Web_app-кнопка reply-клавиатуры не подходит: Telegram не передает ей `initData`.
- Подтверждение присутствия — служебное сообщение: настройки социальной рассылки его не отключают.
- Активная карточка выделена зеленым баннером «СЕАНС ИДЁТ». Завершенная карточка оформлена спокойно. Обе показывают дату и время начала; активная — «сейчас» вместо конца, завершенная — дату и время окончания. Часы в карточках — Новосибирск (UTC+7).
- После завершения сеанса его карточка остается в переписке без кнопки присоединения, со строкой «Было n человек:» (уникальные участники, побывавшие в `smoking`). Старые callback-кнопки не действуют на новый сеанс.
- Под завершенной карточкой участник может оценить сеанс 👍/👎. Один голос на человека, повторное нажатие идемпотентно, оценку можно изменить. Голосовать могут только побывавшие в `smoking` и сохраняющие доступ к комнате. Счетчики видны всем получателям карточки; обновления идут через очередь только для этого сеанса.
- Список включает всех участников: сначала курящие, затем спускающиеся, затем неактивные. Завершенные сеансы, посещения и оценки сохраняются в SQLite. История, удаленная предыдущими версиями, не восстанавливается.
- В Mini App доступны личная статистика по всем комнатам (в том числе покинутым), итоги комнаты и лидерборд текущих участников. Итоги комнаты сохраняют вклад ушедших участников. Чужая статистика видна только в пределах общей комнаты.
- Периоды: «Сегодня» с 06:00 до следующих 06:00 по Новосибирску; «7 дней» и «30 дней» — скользящие окна до текущего момента; «Всё время» — вся сохраненная история и начальный период при открытии статистики. До 06:00 «сегодня» относится к предыдущему утру.
- Один переход в `smoking` — один выход; повторное включение уже активного статуса не увеличивает счетчик, возвращение после ухода увеличивает. Выход относится к периоду по началу, время обрезается границами периода. Незавершенные выходы учитываются до текущего момента; `going` не считается временем курения. Отображение времени — часы и минуты, неполные минуты отбрасываются после суммирования.
- Итоги комнаты: число выходов и сумма времени всех участников, отдельно число общих сеансов и их длительность без умножения на участников. Лидерборд сортируется по числу выходов, затем по времени, затем по ID для стабильности; первые три места отмечены золотым, серебряным и бронзовым кубками.
- Светлая бело-зеленая и темная черно-зеленая темы Telegram, минимализм, большая кнопка, умеренные эмодзи.

## Технические решения

Go, chi, SQLite с WAL и foreign keys, pure-Go драйвер; TypeScript, Vite и собираемый Tailwind без CDN. Статика в Go-бинарнике. Один экземпляр сервиса на VPS. Polling Mini App раз в 5 секунд только при открытом экране.

Схема SQLite версии 2 добавляет оценки и индексы статистики без изменения существующих посещений. Версия 1 обновляется при запуске. Старый бинарник откажется открыть версию 2: его очистка завершенных сеансов несовместима с хранением статистики. Для отката нужна резервная копия базы до обновления.

Telegram initData проверяется по HMAC, сроку и структуре. После проверки выдается случайный токен сессии; в SQLite хранится только его хеш. Токен остается в памяти страницы. Все права проверяет сервер.

Смена статуса, завершение сеанса и постановка уведомлений в очередь выполняются в одной транзакции. Очередь и таймеры переживают перезапуск. Telegram API не предоставляет ключ идемпотентности для sendMessage: при аварии между отправкой и сохранением ответа возможен повтор сообщения; обработчики статусов и кнопок идемпотентны.
