# Участие в разработке

Спасибо за интерес к проекту. Правила простые.

## Локальная среда

Нужны Go 1.25+ и Node.js 22.12+. Node используется только на сборке фронтенда.

```bash
git clone https://github.com/nikitabaskov/vkurilke.git
cd vkurilke
make check
```

`make check` собирает фронтенд, проверяет типы TypeScript, запускает `go vet` и Go-тесты с `-race`. Для `-race` нужен системный C-компилятор; обычная сборка и SQLite работают без CGO.

**Важно:** `web/embed.go` встраивает каталог `web/dist`, поэтому на свежем клоне `go build`, `go vet` и `go test` падают с `pattern all:dist: no matching files found`, пока фронтенд не собран. Сначала `make web` (или сразу `make check`), потом любые команды `go`.

Команды Makefile:

| Команда | Действие |
| --- | --- |
| `make web` | Установить зависимости npm и собрать фронтенд в `web/dist` |
| `make build` | Собрать бинарник `bin/vkurilke` со встроенной статикой |
| `make test` | `go test ./...` |
| `make check` | Проверка типов, `go vet`, тесты с `-race` |
| `make run` | Собрать и запустить |

## Запуск приложения

Приложение читает переменные окружения, а не файл `.env`. Перед запуском экспортируйте их (если файл содержит только доверенные shell-совместимые значения):

```bash
set -a; . ./.env; set +a
./bin/vkurilke
```

Для фронтенда: `npm --prefix web run dev`, Vite проксирует `/api` на порт 8080.

Обхода авторизации нет: нужен настоящий Telegram `initData`. Вне Telegram показывается экран перехода к боту. Для полноценной проверки заведите отдельного тестового бота и HTTPS-адрес разработки (подойдет любой туннель).

## Правила для пул-реквестов

1. Ветка от `main`, один PR — одна тема.
2. `make check` проходит локально. CI запускает то же самое плюс сборку Docker-образа.
3. Новое поведение покрыто тестом. Тесты лежат рядом с кодом: `internal/store/store_test.go`, `internal/api/server_test.go` и другие.
4. Изменения в согласованной продуктовой логике сначала обсуждаются в issue и отражаются в [docs/DECISIONS.md](DECISIONS.md) — этот файл определяет, как приложение должно себя вести.
5. Сообщения коммитов в формате [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`.
6. В описании PR — что меняется и как проверено.

## Стиль кода

- Go: `gofmt`, стандартная библиотека и минимум зависимостей. Новая зависимость требует обоснования в PR.
- Ошибки пользователю возвращаются через типизированные `store.Err*`; внутренние ошибки не утекают в HTTP-ответ.
- SQL пишется параметризованным, доступ проверяется в той же транзакции, что и запись.
- Фронтенд: TypeScript в strict-режиме, без фреймворков. Любые пользовательские данные в HTML проходят через `escape()`.
- Тексты интерфейса и сообщений бота — на русском, обращение на «ты».

## Границы проекта

Проект намеренно маленький: один процесс, SQLite, встроенная статика, одна реплика. Предложения, добавляющие Redis, отдельный Node-сервер, CGO или горизонтальное масштабирование, скорее всего будут отклонены — сначала заведите issue.
